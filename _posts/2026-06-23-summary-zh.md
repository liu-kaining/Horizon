rss · LWN.net · Jun 22, 15:26

**背景**: 全局解释器锁（GIL）是 CPython 中的一个互斥锁，用于保护对 Python 对象的访问，防止多个原生线程同时执行 Python 字节码。这在历史上导致 Python 中的多线程 CPU 密集型程序只能串行运行，限制了多核处理器带来的性能提升。将 GIL 设为可选的努力（在 PEP 703 中正式提出）旨在提供一种向后兼容的方式来运行没有此锁的 Python。

## [eBPF 取代用户空间 Agent，成为安全可观测性的首选](https://www.infoq.cn/article/spibFV8QPwbvac8LAluZ?utm_source=rss&utm_medium=article) ⭐️ 8.0/10

文章解释说，通过将探针直接附加到 Linux 内核的系统调用接口，eBPF 正在成为安全可观测性的首选方法，即使在容器级别被攻破时也能提供一致的可见性。 这一转变意义重大，因为 eBPF 相比传统的用户空间 Agent 提供了更高的效率和更深层的内核级洞察，影响着现代基础设施和云原生环境的监控与安全防护方式。 eBPF 程序是事件驱动的，当特定的钩子（如系统调用或跟踪点）被触发时在内核中运行，能够以低开销提取数据。然而，需要谨慎实施以避免 eBPF 沙箱环境内潜在的安全漏洞。

rss · InfoQ 中文站 · Jun 22, 10:20

**背景**: 在 Linux 系统中，用户空间和内核空间是不同的内存区域；用户空间 Agent 在受保护的虚拟内存中运行，访问权限有限，而内核空间代码以更高权限执行核心系统功能。eBPF（扩展伯克利数据包过滤器）是一项允许沙盒程序在 Linux 内核中运行而无需修改内核源代码的技术，从而实现安全高效的追踪与可观测性。

## [大语言模型提示注入漏洞源于'角色混淆'](https://simonwillison.net/2026/Jun/22/prompt-injection-as-role-confusion/#atom-everything) ⭐️ 8.0/10

Charles Ye、Jasmine Cui 和 Dylan Hadfield-Menell 的研究表明，大语言模型从根本上是通过文本风格而非元数据标签来区分系统提示和用户输入的，这一缺陷被他们称为'角色混淆'。研究通过成功的越狱攻击证实了这一点，其中用户请求被表述为模仿模型内部思考风格，从而覆盖了其安全训练。 该研究揭示了当前大语言模型安全的一个核心结构性弱点，表明在模型实现真正的角色感知之前，提示注入防御可能仍是一场'打地鼠'游戏。它强调攻击者可以使用看似无害的文本大规模、微妙地操纵模型行为，这对已部署 AI 系统的安全性和可靠性构成重大风险。 一项关键发现是，对攻击文本进行'去风格化'处理——重写它使其看起来不像模型预期的内部格式——可以将攻击成功率从 61%降至 10%，这种变化对人类几乎不可见，但对模型影响深远。研究人员在实验中使用了'gpt-oss-20b'等模型，展示了如何通过以特定写作风格附加一个类似策略的声明来混淆模型，使其服从有害请求。

rss · Simon Willison · Jun 22, 23:59

**背景**: 提示注入是一种安全攻击方式，其中恶意指令被嵌入到用户输入中，以操纵大语言模型的输出并绕过其安全准则。当前模型使用特殊标签或格式（如 <system> 或 <user>）来分隔对话的不同部分，但该研究表明，它们并未可靠地将这些标签视为权威边界。相反，模型对谁在'说话'的推断，在很大程度上受到文本本身风格和位置线索的影响。
